## 2. Mandatory vs. Non-Mandatory Criteria for Forked Repositories

* **Mandatory (`Yes`)**: Pipelines and tools strictly required to build, test, document, secure, and release production-grade open-source Node.js artifacts from a forked repository:
  - Source compilation (`test-linux.yml`, `test-macos.yml`, `build-shared.yml`).
  - Packaging & compliance (`build-tarball.yml`, `license-builder.yml`).
  - Code quality & validation (`linters.yml`, `commit-lint.yml`, coverage, and transport test suites).
  - API documentation (`doc.yml`).
  - Release staging & tagging (`create-release-proposal.yml`, `major-release.yml`, `post-release.yml`).
  - Security scanning (`codeql.yml`, `scorecard.yml`).
  - Critical upstream patch updates (`update-openssl.yml`, `update-v8.yml`, `timezone-update.yml`, `tools.yml`).

* **Non-Mandatory (`No`)**: Pipelines and tools that represent upstream-specific OpenJS Foundation internal infrastructure, bot triage, or community moderation:
  - Private Jenkins build farm orchestration (`auto-start-ci.yml`, `commit-queue.yml`).
  - Internal Slack webhook alerts (`notify-on-push.yml`, `notify-on-review-wanted.yml`).
  - Upstream contributor guidance & AI spam filtering (`contributor-guidance.yml`).
  - External consortium test ingestion (`daily-wpt-fyi.yml`).
  - Auxiliary NixOS derivation caches (`nix-changes.yml`, `nix-changes-comment.yml`).
  - Community triage bots (`stale.yml`, `close-stalled.yml`, `label-pr.yml`, `label-flaky-test-issue.yml`, `author-ready-conflicts.yml`, `comment-labeled.yml`).
  - Dedicated bare-metal micro-benchmarking hardware (`benchmark.yml`).
