# Technical Impact & Risk Assessment: Restricted Tools, Infrastructure, and Alternate Approaches

## Executive Context: GitHub Enterprise + Public Repo Open-Source Release Model

When maintaining an open-source product fork within **GitHub Enterprise** using a **Public Repository**, certain upstream tools, build farms, cloud caches, and notification endpoints are proprietary, access-restricted, or vendor-locked to the original upstream foundation (OpenJS Foundation). 

To ensure zero failing pipelines and complete self-containment, our **Dual-Mode Architecture** replaced all vendor-restricted tools with functional **GitHub-Native alternatives**. 

This document provides an empirical, evidence-checked risk assessment evaluating the **impact, risks, mitigations, and enterprise solutions** resulting from these alternate approaches.

## Technical Recommendations for the Release Engineering Team

To achieve a production-grade open-source release while maintaining zero financial expenditure on third-party licenses:

1. **Core Release Pipeline Gating**:
   - Treat the **24 release-critical workflows** (e.g. `build-tarball.yml`, `test-linux.yml`, `test-macos.yml`, `coverage-windows.yml`, `linters.yml`, `codeql.yml`, `license-builder.yml`) as mandatory release gates.
   - Treat the **21 community/bot workflows** (e.g. `auto-start-ci.yml`, `commit-queue.yml`, `daily-wpt-fyi.yml`, `stale.yml`, `close-stalled.yml`) as non-blocking.
2. **ARM64 Architecture Strategy**:
   - For routine PR validation and smoke tests, rely on the free standard `ubuntu-latest` fallback.
   - For official General Availability (GA) ARM64 release binaries, attach a free self-hosted ARM64 runner (such as an Oracle Cloud Free Tier Ampere A1 instance) to ensure native silicon execution without incurring per-minute managed runner fees.
3. **Automated Release PR Triggering**:
   - Enable **"Allow GitHub Actions to create and approve pull requests"** in repository settings (under Settings > Actions > General) so release proposals generated via `$GITHUB_TOKEN` trigger downstream CI validations.
4. **Security & Compliance Verification**:
   - Keep `codeql.yml` and `scorecard.yml` active. On a public repository under GitHub Enterprise, both provide enterprise-grade vulnerability scanning and OpenSSF supply-chain verification at **\$0.00 cost**.
